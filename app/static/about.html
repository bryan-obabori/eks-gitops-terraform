About the project

Built to make the full DevOps path visible

Project 2 is a hands-on platform engineering project that demonstrates how application source, CI, infrastructure as code, GitOps, Kubernetes, and AWS-native networking fit together.

Project 1

Prove the delivery pipeline

The first version established the fundamentals: Go, Docker, Kubernetes, Helm, GitHub Actions, Argo CD, and EKS.

Project 2

Rebuild it with explicit platform ownership

This version adds Terraform-managed AWS networking and EKS, private worker nodes, EKS Pod Identity, AWS ALB ingress, and a self-contained CI/GitOps workflow.

Core ideas

What this project demonstrates

Infrastructure as Code

Terraform declares the AWS network, EKS cluster, platform services, and GitOps bootstrap boundary.

Immutable Delivery

Each successful application build is published with a unique run-specific container tag.

GitOps Reconciliation

Argo CD continuously reconciles the Helm-defined application state stored in Git.

Design principle

Clear ownership, fewer hidden steps

Terraform owns infrastructure and bootstrap resources. Argo CD owns application reconciliation. The AWS Load Balancer Controller owns the ALB generated from Kubernetes Ingress. Each tool has a deliberate boundary.
