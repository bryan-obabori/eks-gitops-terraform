CI/CD Pipeline

From commit to Kubernetes rollout

The application pipeline separates continuous integration from continuous delivery while using Git as the deployment source of truth.

01

Source

Application changes are pushed under app/.

02

Test & Build

GitHub Actions runs the Go test suite and builds the application.

03

Containerize

Docker Buildx produces a linux/amd64 image for the EKS runtime.

04

Publish

The image is pushed to Docker Hub with an immutable run-<ID> tag.

05

GitOps Update

The pipeline updates the desired image version stored in Helm values.

06

Reconcile

Argo CD detects the Git change and syncs the desired state into EKS.

07

Rollout

Kubernetes replaces the workload with the newly published application image.

Continuous Integration

Test → Build → Publish

CI verifies the source and turns it into a versioned deployable artifact.

Continuous Delivery

Git → Argo CD → EKS

CD begins from the desired state committed to Git, not from direct cluster mutation by the CI runner.
